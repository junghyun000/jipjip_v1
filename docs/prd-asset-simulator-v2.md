## 1. 문제 정의

### 1.1 v1.0 사용성 회고 (실측 기반)
v1 구현 후 사용자 피드백:
- **UI가 너무 엉망** — 좌측 입력 패널이 50+ 필드로 길고 산만
- **사용성이 안 좋음** — 어디부터 봐야 할지, 뭐부터 입력해야 할지 불명확
- **너무 번잡스럽게 입력해야 함** — 결과를 얻기 전에 많은 결정을 요구함

### 1.2 근본 원인 분석

| 문제 | 원인 |
|---|---|
| 입력 패널 길이 | 8개 동등 섹션 × 각 6~10개 컨트롤 = 약 50필드 |
| 시각 노이즈 | 멀티모드(슬라이더 + 단계 버튼 + 숫자) 동시 노출 |
| 결과 가시성 부족 | 출력이 입력 아래에 위치 → 스크롤 없이 안 보임 |
| 우선순위 불명확 | 모든 입력이 동등 레벨, "핵심 6~7개"가 묻힘 |
| 결정 피로 | 라이프 이벤트 8개 카드가 처음부터 모두 노출 |

### 1.3 핵심 인사이트
사용자는 단 하나의 질문에 답을 찾고 있다:

> **"우리 부부, 75세 실버타운 입주 후에도 자금 충분할까?"**

입력 50개는 그 답을 얻기 위한 수단일 뿐, 그 자체가 가치 있는 게 아니다. **답(달성률)이 가장 크게 보이고, 입력은 답이 마음에 안 들 때만 조정하면 된다.**

## 2. 목표 & 성공지표

| 구분 | 내용 |
|---|---|
| 1차 목표 | 첫 진입 5초 이내에 **"달성률 X%"** 큰 글씨로 한눈에 확인 |
| 2차 목표 | **핵심 6 카드**로 80% 시나리오 커버, 나머지는 점진 노출 |
| 3차 목표 | 입력 1회당 시각 인지 부담 50% 이상 감소 |
| 4차 목표 | 모바일(≤768px)에서도 동일 사용성 |

**성공지표**:
- 첫 화면(스크롤 X)에 결과 + 6개 핵심 입력 모두 노출
- "고급 설정"을 펼치지 않고도 의미 있는 조정 가능
- 라이프 이벤트 적용/미적용을 단일 토글로 비교 가능

## 3. 디자인 원칙

1. **결과 우선 (Result-First)** — 화면 최상단에 항상 달성률·예상 자산 노출
2. **점진 노출 (Progressive Disclosure)** — 기본 접힘, 사용자가 필요할 때만 펼침
3. **단일 진입 (Single Affordance)** — 입력 1개당 컨트롤 1개. 멀티모드 제거
4. **스마트 기본값 (Sane Defaults)** — 대부분 사용자는 기본값으로 충분
5. **카테고리 라벨링 (Category Grouping)** — 8개 섹션 → 3개 그룹(Quick / Advanced / Events)
6. **즉시 피드백 (Instant Feedback)** — 입력 변경 시 100ms 이내 결과 갱신

### 4.2 입력 단순화 표

| v1 (현재) | v2 (목표) | 효과 |
|---|---|---|
| 50+ 개별 필드 | **핵심 6 카드** + 상세 접힘 | 시각 부담 −80% |
| 멀티모드(슬라이더 + 단계 + 직접) | **슬라이더 1개** + 카드 클릭으로 정밀 조정 | 인지 부담 −66% |
| 8개 동등 섹션 | **3 레벨** (Hero / Quick / Advanced) | 우선순위 명확 |
| 자산 3-bucket 개별 입력 | **합계** + 비율 슬라이더 (advanced에서 분리) | 1차 결정 단순화 |
| 모든 수익률 개별 슬라이더 | **시장 가정 단일 토글** (보수/중립/공격) | 가정 결정 −67% |
| 라이프 이벤트 8 카드 노출 | **단일 ON/OFF 토글** + advanced 펼침 | 첫 화면 노이즈 제거 |
| 입력 → 결과 (스크롤 필요) | 결과 → 입력 (결과가 sticky) | 피드백 즉시 |

### 4.3 차트 단순화

| v1 | v2 |
|---|---|
| 3개 차트 동시 노출 | **1개 메인 차트** + "더 보기" 모달 |
| 자산 적층 / 소득·저축 / 거주 소진 | 메인: **자산 + 목표선 + 라이프 이벤트 마커** 통합 |
| 항상 보임 | 차트 1개 + 상세 3개는 모달 |

## 5. 기능 명세

### 5.1 결과 히어로 카드 (Hero)

**위치**: 화면 최상단, 탭 바 바로 아래. 모바일에서는 sticky.

**구성**:
- 거주 기간 토글 [10년] [20년] [30년] — 가로 3-탭
- **달성률** (가장 큰 글씨, 72px)
  - 예: `💚 161%`
  - 상태별 색·이모지:
    - ≥100%: 💚 초록
    - 70~99%: 🟡 노랑
    - <70%: 🔴 빨강
- 보조 텍스트 (1줄):
  - `예상 50.7억 / 목표 31.6억`
- 한 줄 알림:
  - 달성: `✅ 10년 거주 충분 (GAP +19.1억)`
  - 부족: `⚠️ 목표에 N억 부족 — 저축률 또는 등급 조정 권장`
  - 자금 고갈: `❌ 거주 N년차 자금 고갈`

**모바일**: 위 구조 그대로, 폭 100%, sticky 유지.

### 5.2 빠른 입력 6 카드

각 카드 공통 구조:
- 상단: 아이콘 + 라벨 (작은 글씨)
- 중앙: **현재 값** (큰 글씨)
- 하단: 1개 컨트롤 (슬라이더 또는 셀렉트 또는 토글)
- 클릭 → 인라인 펼침으로 정밀 조정

#### 카드 1 — 우리 (Profile)
```
👫 우리는
와이프 28세 · 남편 33세
[ 클릭으로 변경 ]
```
- 클릭 → 인라인에서 와이프/남편 나이 + 입주 나이 직접 입력

#### 카드 2 — 자산 (Net Worth)
```
💰 현재 자산
3억 (현금 1억 + 투자 2억)
━━━●━━━━━━ 0~50억
```
- 메인 슬라이더: **총 자산** 0~50억
- 슬라이더 변경 시 기존 비율 유지하며 cash/inv 동시 조정
- 클릭 → 현금/투자/부동산 개별 입력 (advanced 동일)
- 부동산 상태: 우측 작은 라벨 (`없음` / `보유 5억` / `5년 뒤 7억`)

#### 카드 3 — 소득 & 저축 (Income)
```
💼 소득 & 저축
가구 1.14억 / 월 309만 저축
━━━●━━━━━━ 저축률 30%
```
- 메인 슬라이더: **저축률** 0~60%
- 부가 정보: 월 저축액 = 가구소득 × 0.83 × 저축률 / 12
- 클릭 → 와이프/남편 연봉 분리, 실수령, 소득증가율

#### 카드 4 — 실버타운 (Tier)
```
🏡 실버타운
중급 (3억 / 월 250만)
[최상급] [상급] [중급✓] [하급]
```
- 4-탭 등급 선택
- 클릭 → 보증금/월비용 직접 조정 + 반환형 토글

#### 카드 5 — 입주 (Stay)
```
🌅 입주 계획
와이프 75세 (2073년)
[10년] [20년✓] [30년]
```
- 거주 기간 토글 — Hero와 동기화
- 클릭 → 입주 나이 미세 조정 (60~90)

#### 카드 6 — 시장 가정 (Outlook) ⭐ 신규 단순화
```
📈 시장 가정
중립 (인플레 3% / 투자 6%)
[보수] [중립✓] [공격]
```

**3-프리셋 단일 토글**:

| 프리셋 | 인플레 | 투자 수익 | 현금 수익 | 부동산 | 소득증가 |
|---|---|---|---|---|---|
| **보수** | 4% | 4% | 1.5% | 2% | 2% |
| **중립** (default) | 3% | 6% | 2.5% | 3% | 4% |
| **공격** | 2% | 8% | 3.5% | 4% | 6% |

- 클릭 → 5개 항목 개별 슬라이더 (advanced 동일)
- "커스텀" 상태: 사용자가 advanced에서 1개라도 변경 시 라벨 `커스텀`으로 변경

### 5.3 자산 추이 차트 (메인)

**구성**:
- 라인 차트 (Chart.js)
- X축: 와이프 나이 28~75
- 시리즈:
  - 예상 총자산 (실선, 굵음)
  - 목표 자산선 — 입주 시점 needsByN[N] (점선, 빨강)
  - 라이프 이벤트 발생 시점 (↓ 마커, 회색)
- 입주 시점 vline (회색)
- 부동산 매입/매도 시점 vline (옵션)

**"더 보기" 버튼** → 모달 (전체화면):
- 차트 1 (확대): 3-bucket 적층
- 차트 2: 소득·저축·연금
- 차트 3: 거주 후 자금 소진

### 5.4 라이프 이벤트 토글 영역

**기본 모드 (접힘 상태)**:
```
🪦 라이프 이벤트 [ON ✓]
양가 부모님 장례식·중대 질병·시장 충격 평균값 반영
( ~75세까지 누적 약 2.9억 예상 )
[ 개별 조정 → ]
```
- 단일 토글로 전체 ON/OFF
- 토글 OFF 시 결과에서 라이프 이벤트 완전 제외 (시각 비교 즉시 가능)

**개별 조정** (펼침 or 모달):
- v1과 동일한 8개 카드 (스타일 유지)
- 단, 항상 노출이 아닌 모달 또는 별도 섹션

### 5.5 상세 설정 (Accordion)

기본 접힘. 클릭 시 펼침. 각 섹션은 v1과 거의 동일하나 단순화:

1. **자산 세부** — 현금/투자/부동산 개별 입력, 부동산 매입 시점, 매도 처리
2. **소득 세부** — 와이프/남편 분리, 실수령 환산, 피크 나이
3. **시뮬레이션 가정** — 인플레/투자/현금/부동산/소득증가율 개별, 저축 분배, 거주 중 실질수익률
4. **은퇴 & 연금** — 은퇴 나이, 연금 자동/수동
5. **버퍼** — 의료·예비비

**제거**:
- 멀티모드 입력 (슬라이더만 유지, 직접 입력은 카드 클릭 시 인라인)
- 단계 프리셋 버튼 (시장 가정 토글로 대체)

### 5.6 모바일 최적화

- Hero 카드: 폭 100%, sticky
- 빠른 입력 6 카드: 1열로 적층, 각 카드 큰 사이즈
- 상세 설정: 전체화면 모달 가능
- 차트: 폭 100%, 세로 380px

## 6. 데이터 모델

**DB 스키마 변경 없음**. v1 그대로 사용.

**클라이언트 state 추가**:
- `outlook`: `'conservative' | 'neutral' | 'aggressive' | 'custom'`
  - DB 저장 시 별도 컬럼 불필요 (인플레/투자값으로 추론 가능)
  - 로드 시 인플레값으로 매칭: `infl=0.03 && inv=0.06 → 'neutral'`, 미스매치 → `'custom'`
- `lifeEventsEnabled`: `boolean` (전체 토글)
  - 토글 OFF 시 모든 이벤트의 `enabled` 임시 무시 (실제 events 배열은 변경 안 함)

**localStorage 키**:
- v2는 신규 키 `jipjip:sim:state:v2` 사용
- 첫 진입 시 v1 키(`jipjip:sim:state:v1`) 있으면 자동 이관 후 v1 키 보존 (롤백 대비)

## 7. 마이그레이션 전략

- DB 마이그레이션 없음
- 기존 시나리오 100% 호환

- 시나리오 저장 시 v1과 동일한 컬럼 채움
- **롤백**: simulator.js를 v1 버전으로 revert만 하면 됨 (DB/스키마 변경 없음)

## 9. 에러 케이스 & 입력 검증

| 케이스 | 처리 |
|---|---|
| 자산 합계 슬라이더가 0 | 카드에 회색 처리 + Hero 알림 "자산 입력 필요" |
| 시장 가정 advanced에서 값 변경 | 카드 6 라벨 `중립` → `커스텀` |
| 시장 가정 토글 클릭 | advanced 5개 값 즉시 갱신 |
| 라이프 이벤트 토글 OFF | 모든 이벤트 임시 비활성, 결과 재계산 |
| 라이프 이벤트 OFF + 개별 조정 펼침 | 카드는 보이되 disabled 상태 + 상단 안내 |
| 모바일에서 sticky Hero가 차트 가림 | 차트 카드 상단 padding 추가 |
| v1 → v2 첫 진입 | v1 state 자동 이관 + 토스트 "새 디자인으로 업데이트" |
| 시나리오 로드 시 outlook 불일치 | `'custom'`으로 라벨링 |

## 12. 한계 & 가정 리스크

- **차트 1개로 단순화**로 일부 정보가 모달에 숨겨짐 → 첫 화면 사용성과 정보량의 트레이드오프
- **시장 가정 단일 토글**은 5개 값을 묶어 동시 변경 → 정밀 조정은 advanced 필요 (의도적 단순화)
- v1과 v2 동시 운영 안 함 → 한 번에 전환, 롤백은 git revert
- 라이프 이벤트 토글 OFF는 events 배열을 변경하지 않고 임시 비활성 → 시나리오 저장 시 ON 상태로 저장됨 (의도적, 토글은 일시적 비교 도구)
